# 架构

pnpm workspace，TypeScript，Node 26。依赖方向自上而下：

```
apps/desktop ─┐
apps/web ─────┼─> packages/protocol ─> packages/domain
apps/cli ─────┘
apps/daemon ──> packages/control ─> packages/adapters, packages/store, packages/protocol, packages/domain
```

## 命令的路径

1. 客户端发命令信封到 `POST /v1/commands`([接口](api.md))。
2. `Control.execute` 校验信封和 `input`,会话凭证只放行它角色允许的命令，查幂等键，在一个 SQLite 事务里调 `commands.ts` 汇总的处理函数。
3. 处理函数改状态表、写事件、往 outbox 排后续工作；事件经 `GET /v1/events` 和 `WS /v1/events/ws` 推给客户端。
4. `scheduler.ts` 按 outbox 和定时器推进：准备 worktree(`provisioning.ts`)、起回合(`session.ts`、`native-session.ts`)、送达权限回答(`approvals.ts`)、合并(`workbench-session.ts` 调 `landing.ts`)、删 worktree 和审查目录，并推进摸底与改动解读会话。

## 带工具的会话

`session.create` 带 `purpose: 'conductor'` 开的会话，凭证角色是 `conductor`,可以是工作树会话，也可以是就地会话。Pantheon 只给它多 `sessionTools.conductor` 里的工具和一段说明(`conductor.ts` 的 `CONDUCTOR_INSTRUCTIONS`),计划、拆活和子 agent 用运行时自己的。`conductor.*` 工具对应 `conductor.ts` 的命令;`project_read` 和 `memory_*` 是规划会话也用的同一组命令(`project.read`、`memory.*`),记忆只经工具读，不自动注入回合;`draw` 和项目搭建会话的画图是同一个命令(`visual.draw`):

- `request_review`(`conductor.review`):别家运行时审它自己或它起的会话已提交的改动，结果作为一条消息回到它。
- `report_ready`(`conductor.ready`):把它自己或它起的会话交给门禁并落地；这份工作最近一次审查还有未解决的阻塞发现时拒绝(`review_blocking_open`)。对自己调用时，门禁和落地在这个回合结束后开始。用户自己点合并不受这条限制。
- `spawn_session`(`conductor.spawn`):从调用者当前提交切一个新工作树，起一个不带工具的普通会话，记 `spawned_by`;权限模式只收 `ask`(默认)和 `auto_edit`;项目超预算时拒绝(`budget_exceeded`);每个带工具会话同时最多 4 个在跑回合(有排队或在跑的回合)的被起会话。被起会话的回合完成或失败时,`afterSpawnedTurn` 告诉起它的会话。
- `message_session`(`conductor.message`):给 `spawned_by` 是自己的会话发 `send` 或 `steer`,按用户的发送排回合;每个被起会话 60 秒内最多 2 条(数 `session.conductor_messaged` 事件),超了 `rate_limited`。
- `stop_session`(`conductor.stop`):对自己起的会话，不带 `close` 是打断当前回合(`interruptSession`),带 `close` 是关闭并丢弃工作树(`stopWorktreeSession`,`by: 'lead'`)。
- `read_state`(`conductor.state`):项目的改动(`changes.ts`,最多 30 条,24 小时前合并的不列)和等用户的事(最多 20 条);自己起的会话那一行带 `usage`(会话累计的输入、输出、缓存读 token,跑过的回合数和这些回合从 `turn.running` 到结束的毫秒数)。
- `read_needs_you`(`conductor.needs_you`):`needsYou` 的本项目条目，只留种类、原因、会话和时间，不带作答动作和请求输入。

放行 `project.read` 也放行了按它检查的本项目只读查询(会话列表、文件、轨迹等),和规划会话一样。替用户批工具审批、设备、发现结论不在表里，主 agent 做不了。

通知不经收件箱:`session-wake.ts` 的 `notifySession` 给目标会话排一个回合，目标在跑时并进已排队的那个通知回合；项目超出预算或会话不收输入时丢弃。

## control 模块分组

- 交互终端:`terminals.ts`(懒加载 node-pty、用户 login shell、内存输出回放、会话结束与无连接超时清理；daemon 的独立 WebSocket 只传输出)
- 入口与上下文:`index.ts`(`Control`)、`commands.ts`(处理函数表)、`context.ts`(`ControlContext`、会话角色的命令范围、daemon 自建会话的提示词)
- 会话:`workbench-session.ts`(`session.create`、列表、diff、门禁、合并、丢弃、改名、置顶、归档、删除、权限模式、`session.fork`、`session.setConnectors`)、`session.ts`(回合队列、发送、插话、打断、停止后台任务、`session.compact`、`session.resolve`)、`native-session.ts`、`checkpoint.ts`(每回合前的隐藏 ref checkpoint、`session.rollback` 按 `scope` 退文件、对话或两者)、`agent.ts`、`session-recap.ts`(每个回合结束和进入等待时写一次会话 recap,记用量、查项目预算)、`approvals.ts`(权限请求和提问，回答送回原生会话)、`session-wake.ts`(`notifySession`、`queueTurn`:给会话排一个回合)、`admission.ts`、`process.ts`、`child-processes.ts`、`non-writer-audit.ts`(只读类会话的写入审计)
- 工作区与隔离:`workspace.ts`、`provisioning.ts`、`workspace-removal.ts`、`git.ts`、`git-config-cache.ts`(按仓库缓存 `runGit` 要中和的 filter 和 merge driver 名单，配置文件、include 目标或仓库目录的签名一变就重查)、`protection.ts`(保护清单；`worktreeSandbox`:工作树会话只能写自己的工作树、源仓库的 objects 和自己的 worktree 元数据目录)、`dependency-folders.ts`、`files.ts`、`in-place-session.ts`(`session.adopt`:外部原生会话在原目录续接，工作区 kind 为 `in_place`)、`native-liveness.ts`(原生会话是否被 Pantheon 之外的进程占着)、`workspace-stale.ts`(陈旧工作树、全部工作树的磁盘占用)、`workspace-files.ts`(`files.read`、`symbols.search`:读文件、按名字找代码声明，范围是会话 worktree 或项目第一个文件夹)
- 合并与门禁:`landing.ts`(改了 `AGENT_CONFIGURATION` 里 agent 配置路径的合并被挡，原因 `protected_paths`)、
  `landing-diff.ts`、`source-git.ts`、`merge-preview.ts`(合并预检和预测冲突共用的 `git merge-tree`)、`validation-executor.ts`(不套沙箱，在候选目录里起一条门禁命令，记退出码、输出和测试数，超时或取消时停掉整个进程组)、`gate-test-counts.ts`(从门禁输出逐行数测试的通过、失败、跳过数)、`environment-check.ts`(`project.environment.verify`、`project.environment.checks`:在一份新 worktree 里按会话拿到的方式准备，再跑门禁命令或基线提议的命令，结果记为 passed、failed 或 inconclusive;基线的检查第一次失败时交回基线会话修一次，门禁失败的信号在那个根目录的 HEAD 上复查一次)、`branch-landing.ts`(`project.land`、`project.landing.read`:用户给项目根和一个不属于会话的分支，在一份新 worktree 里把它 rebase 到根当前检出的分支上、跑这个根的门禁，通过后快进;给了 `message` 先把分支的提交压成一个提交;和同一个根的会话合并排队，一个接一个)。`landing.ts` 跳过关掉的门禁命令，能跳过的命令失败记 `skipped`,按流程参数 `gate_on_fail` 重跑失败的命令，按 `gate_runner` 在候选 clone 或会话 worktree 里跑，环境和用户开的会话一样(`native-session.ts` 的 `inheritedEnvAllowlist`)

## web

Trace 屏的“替你批准的”页(`screens/trace/ApprovedForYou.tsx`)按日期范围列出存下的规则没问你就做的决定，数据由 `data/decisions-for-user.ts` 读 `project.decisions`,旁边可展开按决定种类的通知规则。

`components/visual/` 是会话画的图和固定的图表卡片:`VisualCard.tsx` 的 `VisualFrame` 是带计数、缩放和源码操作的卡框;`GraphDiagram.tsx` 画 graph(ELK 布局在 `graph-layout.ts`),`MermaidDiagram.tsx` 画 mermaid,其中 ER 图和时序图由 `ErDiagram.tsx`、`SequenceDiagram.tsx` 用原生组件画(布局在 `mermaid-layout.ts`);`VegaChart.tsx`、`KlineChart.tsx`、`TableVisual.tsx` 画 vega-lite、K 线和表格;自定义 HTML 跑在 `SandboxFrame.tsx` 里。

会话屏(`screens/sessions/`)的面板：改动、检查(`GateResults.tsx`,按失败、通过、跳过、未跑分组)、计划和浏览器(`BrowserPanel.tsx`,桌面 app 把网页叠在面板位置);`TerminalPanel.tsx` 是对话和面板下方的终端，只在桌面 app 里有。

`screens/sessions/RequestCards.tsx` 的 `RequestCard` 是会话线程里一条权限请求或提问的卡和它的就地操作；要你处理的会话在会话列表的 inbox 分组里(`screens/sessions/session-groups.ts`)。

设置(`screens/settings/`)里的部分页面:

- `GatesPage.tsx`:项目门禁的步骤(可关掉、可设失败时跳过),门禁失败后怎么办(`gate_on_fail`)和门禁在哪跑(`gate_runner`)。页上的环境检查是 `components/EnvironmentCheck.tsx`,发 `project.environment.verify`、读 `project.environment.checks`;基线确认卡(`screens/projects/BaselineBlocks.tsx`)也用它。
- `HarnessPage.tsx`(应用级页面):本机找到的 harness 和它们的可用模型。
- `DevicesPage.tsx`(应用级页面):本机和已配置设备的在线状态、工具、登录状态、会话位和资源占用；能加设备、改标签/资源/会话位、删除(可撤销)、重新探测，发 `device.save` 和 `device.remove`;数据由 `data/devices.ts` 读 `device.list`。
- `ProjectSettingsScreen.tsx`:项目设置，扩展页逐个打开用户级 MCP、skill 和账号连接器。

`components/RuntimeGlyph.tsx` 是 runtime 身份表：界面里每个 runtime 的名字、颜色、图形和排序都从这里取；表外的 runtime 用通用图形，名字就是 runtime 名。`RuntimeGlyph` 和 `ModelMark` 默认 16px。

前端的 `data/workbench-sessions.ts` 查询默认在失败后清空数据；trace、审查显式选择保留上次成功读到的值，并携带成功读取时间和过期状态，由 `components/ReadStatus.tsx` 呈现。事件流在线时重读中的读值不算过期，事件流断开或读取失败才算。合并预检维持默认策略。过期的审查不授权变更操作。

- `crash-daemon.mjs` 在给定数据目录上起 daemon 子进程，发完命令后在指定 failpoint 处 SIGKILL 自己。

- `desktop-app.mjs` 检查桌面 app 的打包产物是否比源码新，并拉起和关闭真实 Electron app;`projectShown` 等侧栏显示出项目，首次启动时从项目列表点开。
- `event-client.mjs` 是事件 WebSocket 客户端、事件投影、慢读的事件 socket 和 `waitFor` 轮询。
- `workspace-root.mjs` 在仓库的 `node_modules/.cache/` 下建托管工作树的根目录。

共用测试 helper:`tests/web/web-hook-host.ts` 的 `reactMock`、`mount`/`unmountAll` 替代各文件内联的 `vi.mock('react', …)` 和本地 `mount()`;`tests/web/web-live-stores.ts` 的 `liveStores` 替代内联的 zustand `createStore` mock;`tests/web/web-fake-dom.ts` 替代各文件的 `FakeNode`/`FakeElement`/`FakeDocument`;`tests/web/web-toast-store.ts` 的 `mountToastStore` 替代内联的 toast store;`tests/helpers.ts` 的 `settle` 和 `insertSession` 替代 control 测试里的本地 `settle(f, session)` 和 `session(f, …)`。

`tests/acceptance/verify/` 是端到端驱动：启动隔离的 fixture daemon 和桌面 app,经 CDP 按功能清单点击并核对 daemon 状态。

`tests/eval/` 是评测运行器，量「合并进 main 的结果里通不过隐藏检查的比例」:

- `tasks/<任务名>/task.json` 是冻结任务，取自本仓库的提交历史：起点是一个提交的父提交，隐藏检查是那次提交的测试。隐藏检查的文件不存副本，`hidden_files` 只列路径，内容从原提交取。
- `lib/tasks.mjs` 读取并校验任务。
- `lib/check.mjs` 在仓库根下被忽略的 `.eval-work/` 里解出起点和原提交两棵树，各跑一次隐藏检查。
- `lib/run.mjs` 做一次运行：新仓库、新 daemon、用脚本的 lead 写一个任务的计划并派发，运行结束后在 main 的树上跑隐藏检查。
- `lib/fixture-tasks.mjs` 是 fixture 运行时上的 7 种任务行为和两个条件(只有验收命令、加一条独立检查),每个条件下合并几次、漏过几次是已知的。
- `lib/frozen-tasks.mjs` 把冻结任务接到 `lib/run.mjs`:仓库只有起点一个提交并装好依赖(产品把检出里的 `node_modules` 拷进工作树和门禁的候选树，门禁不装依赖),任务的验收命令就是合并时的验收，隐藏检查先叠上原提交的测试文件再跑；`reference` 适配器是 fixture 换了名字，第一个回合把 scope 里的文件写成原提交上的内容再提交，用来证明这条路不用模型也能合并并通过隐藏检查。
- `lib/report.mjs` 算漏过率和完成率的 Clopper–Pearson 区间、两个条件按任务配对的精确符号检验，写成 Markdown。

单元和集成测试只用 fixture 适配器，不调用真实模型；验收里 `mode: live` 的案例只在 `scripts/acceptance.mjs --allow-live` 下跑真实模型。`tests/tsconfig.json` 由根 `tsconfig.json` 引用,`pnpm build` 和 `pnpm typecheck` 都检查测试类型;测试按包名引 `react`、`react-dom`、`@anthropic-ai/claude-agent-sdk`,由它的 `paths` 和 `vitest.config.ts` 的 alias 指到 `apps/web`、`packages/adapters` 里的副本。

### Agent runtime diagnostics

`trace.time` uses bounded reads of the local lifecycle events and native span cache for the project's selected period or one session. `trace-time.ts` sweeps request intervals once for elapsed wall time, reports cross-category overlap separately, and computes cumulative observed operation time with nested intervals removed from their containers. It returns compact samples for navigation. It does not trigger native transcript indexing or a model call. Gate time is shown separately. On the conversation surface, `visual.draw` emits a visual item in the transcript. Structured charts use the app renderers and custom HTML stays in the existing sandbox. The conversation presentation uses the surrounding message surface, while pinned visuals use their own card.

`runtime-findings.ts` pairs indexed daemon lifecycle events and cached native tool intervals. `runtime-review.ts` freezes a bounded projection for a separate read-only analysis session. Its credential only exposes paged evidence and structured report submission. `project.read` includes at most three user-shared conclusions. User-recorded experiment outcomes can produce a draft in the existing memory workflow.

`apps/daemon/src/runtime-otel.ts` tails committed lifecycle events to an opt-in OTLP HTTP/JSON log exporter. UI reads and scheduling use the local event database. The exporter batches, times out and backs off independently of the scheduler.

A runtime review skill and the Trace action share the evidence review contract in `packages/control/src/runtime-review.ts`. Approval decisions and runtime confirmation are paired separately. Native-only coverage and inferred parent links remain visible in the evidence. Optional runtime diagnostics degrade independently.
